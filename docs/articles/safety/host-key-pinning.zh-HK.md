---
title: 主機金鑰批准同釘選
summary: 路由器嘅 SSH 主機金鑰批准一次就會釘選，其他裝置冒充唔到你嘅路由器。
---

程式經 SSH 連接路由器時，路由器會出示一條主機金鑰，即係識別嗰部裝置嘅指紋。主機金鑰釘選嘅意思係：你批准一次指紋，程式就記住佢，之後如果見到唔同嘅指紋，就拒絕繼續。

> [!NOTE]
> 指紋檢查已經喺 SSH 用戶端實作。批准畫面同「金鑰已改變」畫面仍然**開發中**。

## 第一次連線

1. 設定期間程式連線，收到路由器嘅主機金鑰。
2. 程式顯示指紋，格式係 `SHA256:` 加一段短字串，並提示「請批准路由器嘅主機金鑰以繼續。」
3. 如果你喺路由器睇到指紋，就核對；如果喺可信任嘅網絡，就可以直接接受。
4. 批准之後，指紋就同連線一齊儲存。

> [!EXAMPLE]
> 指紋樣子嘅範例，並非你路由器嘅：`SHA256:Qm9ndXNFeGFtcGxlRmluZ2VycHJpbnRPbmx5`。

## 之後嘅連線

每次連線都會將出示嘅指紋同已釘選嘅比較。一樣嘅話，乜都唔使顯示；唔一樣，程式會喺傳送任何憑證之前停低，並顯示「路由器出示嘅主機金鑰同你批准過嘅唔同。」

## 金鑰改變嘅時候

| 可能原因 | 點做 |
| --- | --- |
| 你將路由器重設做原廠設定，或者特登更改咗 SSH 金鑰 | 確認係你預期嘅路由器，然後批准新金鑰。 |
| 你用另一部路由器取代咗同一個位址嘅舊機 | 確認硬件之後批准新金鑰。 |
| 有人攔截連線 | 唔好批准。檢查網絡同位址。 |

只有擁有者可以批准新金鑰。批准會取代原本嘅釘選，並記入[改動歷史](change-history.md)。

## 點解重要

冇釘選金鑰嘅話，網絡上嘅攻擊者可以回應連線，攞到你嘅憑證。釘選令首次連線之後呢個機會消失，所以第一次批准值得留心一下。

## 限制

- 「首次使用即信任」代表第一次批准只係同你當時嘅網絡一樣安全。有機會就核對指紋。
- 釘選只涵蓋 SSH 連線。其他流量，例如瀏覽器開路由器自己嘅網頁，有佢自己嘅憑證規則。
