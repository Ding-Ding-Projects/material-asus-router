---
title: 斷線保護
summary: 改動令程式失去連線時，路由器上嘅計時器會自動還原舊值。
---

有啲改動會切斷程式同路由器之間嘅連線，例如新嘅路由器位址、唔同嘅 DHCP 範圍、你正喺度連緊嗰個網絡嘅 Wi-Fi 重新啟動，或者防火牆規則。一旦斷線，程式就送唔到「改返轉頭」嘅指令。斷線保護嘅做法，係將救援機制放喺路由器自己身上。

> [!NOTE]
> 保護腳本嘅產生、計時指令同取消指令已經喺 `server/changes/guard.mjs` 實作。喺真實路由器上逐類改動測試仍然進行緊，而模擬路由器只係模擬計時器。

## 運作方式

寫入改動之前，程式會先傳一個細腳本去路由器：佢會還原舊值、提交、重新啟動同一批服務，然後刪除自己。路由器背景有個計時器，等到時間就執行呢個腳本。如果改動之後程式仲連到路由器，就會取消計時器；連唔到嘅話，唔使任何人做嘢，路由器會自己還原。

```text
 程式                                   路由器
  |                                      |
  | 1. 儲存舊值                           |
  | 2. 傳送還原腳本並啟動計時器 ->          計時器：90 秒（背景）
  | 3. 寫入新值、提交、重新啟動服務 ->      新設定生效
  |                                      |
  | 4. 重新連線並讀返一個數值              |
  |        |                             |
  |   連得到？                            |
  |     係 -> 5a. 取消計時器 ------------->  計時器停止，腳本刪除
  |     否 -> 5b.（程式斷咗線）              計時器觸發：舊值還原，
  |                                         服務重新啟動，腳本刪除
  v                                      v
```

## 逐步說明

1. **儲存舊值**，記入改動歷史。
2. **啟動保護。** 腳本以編碼形式傳去路由器嘅暫存資料夾，計時器開始。預設時間係 90 秒，可設定範圍係 5 至 900 秒。
3. **套用改動**，受影響嘅服務重新啟動。
4. **程式嘗試重新連線**，讀返一個數值確認改動生效。
5. 路由器有回應就**取消保護**；冇回應就由計時器**自動觸發**。

## 幾時會啟動保護

| 改動 | 保護 |
| --- | --- |
| 路由器位址、子網絡、DHCP 範圍 | 啟動 |
| 你正使用嗰個頻段嘅 Wi-Fi 設定 | 啟動 |
| 防火牆同連接埠轉發規則 | 啟動 |
| 互聯網連線類型同 DNS | 啟動 |
| 顯示名稱同標籤 | 唔需要 |
| 重新啟動 | 唔使用，請睇[雙重確認](super-confirmation.md) |

## 你會見到乜

計時器行緊嘅時候，程式會顯示倒數同一句：「如果呢個頁面連唔到路由器，會自動還原。」程式重新連線成功就會有簡短確認。如果路由器已經還原，等過咗延遲時間再開程式，[歷史](change-history.md)會將該改動標示為**由保護還原**。

> [!WARNING]
> 保護只係防止失去連線，並唔會防止「行得通但係設定錯」，例如錯咗嘅 Wi-Fi 密碼。請細心睇預覽，有需要就用[還原](undo-changes.md)。

## 限制

- 啟動計時器時路由器必須運作中。延遲期間停電，路由器可能剩低一半改咗嘅數值。
- 如果路由器嘅時鐘或者 shell 好特別，計時器可能啟動唔到。程式會確認計時器已經啟動，否則拒絕套用。
- 將延遲設得太短，可能令一個慢但成功嘅改動被還原。除非有原因，否則用預設值。
