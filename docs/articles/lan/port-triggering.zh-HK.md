title: 端口觸發
summary: 只喺裝置用緊另一個端口嘅時候先開一個端口、同端口轉發有咩分別，以及點解一次淨係得一部裝置用。
---

端口轉發係門一直開住。**端口觸發**係屋企入面嘅裝置喺「觸發」端口向外連線之後，先至開門。路由器會短時間開放「進入」端口俾嗰部裝置，之後再關返。

> [!NOTE]
> **開發中。** 端口轉發規則已完成（見[端口轉發](../router/port-forwarding.md)）。端口觸發編輯器未做。

## 比較

| | 端口轉發 | 端口觸發 |
| --- | --- | --- |
| 門幾時開 | 一直開 | 觸發後先開 |
| 要唔要固定裝置位址 | 要 | 唔使 |
| 一條規則可以俾幾多部裝置用 | 每個端口一部 | 每條規則一次一部 |
| 閒置時嘅風險 | 端口可以俾人探測 | 乜都冇開 |

## 實例（示範）

一個舊遊戲向外連去 6000 端口，然後期望伺服器喺 7000 至 7010 連返入嚟。

| 欄位 | 值 |
| --- | --- |
| 觸發端口 | 6000，TCP |
| 進入端口 | 7000 至 7010，TCP |

任何屋企裝置連去 6000，路由器就會俾伺服器經 7000 至 7010 入返嗰部裝置，直到連線靜咗。

## 幾時啱用

用唔固定端口嘅裝置，或者屋企人輪流玩同一個遊戲。如果裝置每次都用同一個端口，普通[轉發](../router/port-forwarding.md)更簡單。

## 限制

- 一次只有一部裝置可以擁有觸發，第二部觸發同一條規則會取代第一部。
- 要先有入站連線先至有出站嘅應用程式用唔到。
- 同所有開咗嘅端口一樣，應用唔用就要刪走規則。

## 步驟（計劃中）

1. 打開**端口轉發**範圍，揀觸發。
2. 輸入觸發端口、進入範圍同協定。
3. 睇預覽：會清楚顯示邊啲端口幾時開。
4. 行應用程式測試，再睇路由器記錄。
