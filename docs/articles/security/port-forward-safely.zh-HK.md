---
title: 安全地轉發端口
summary: 一步一步將一個端口開俾一部裝置、測試，並將風險減到最細。
---

端口轉發係將去你公開位址某個端口嘅流量，送去屋企入面一部裝置。用於遊戲伺服器、鏡頭觀看程式，或者你自己架設嘅網站服務。呢篇用程式已經支援嘅規則（見[端口轉發](../router/port-forwarding.md)）。

::sim[port-forward]

*上面嘅面板係示範，裝置同端口都係虛構，唔會掂你嘅路由器。*

## 開任何嘢之前

1. **真係需要嗎？** 視像通話程式、串流盒同大部分遊戲機都唔使。先睇吓冇轉發應用程式得唔得。
2. **俾目標裝置固定位址。** 做一個[位址保留](../router/address-reservations.md)。規則指住會變嘅位址，最後會指去陌生人。
3. **用最窄嘅規則。** 一個端口、一個協定、一部裝置，避免範圍。
4. **更新裝置**同應用程式。有已知漏洞而暴露嘅程式就係入口。

## 步驟

1. 打開**端口轉發**，撳**新增**。
2. 取一個一年後仲認得嘅名。
3. 揀裝置、協定、外部端口同內部端口。兩個用同一個數字最簡單。
4. 睇預覽，會顯示「198.51.100.40 端口 25565，TCP」同裝置名。
5. 確認。改動行正常安全改動途徑，可以還原。

## 喺外面測試

喺屋企裏面測試通常會成功，但證明唔到乜。叫朋友測試，或者手機熄 Wi-Fi 用流動數據，或者用外部端口檢查服務。失敗嘅話，跟[按症狀疑難排解](../reference/troubleshooting-by-symptom.md)逐項檢查：雙重 NAT、裝置自己嘅防火牆、協定錯咗，同供應商封鎖端口。

## 將風險減到最細

| 應該 | 唔應該 |
| --- | --- |
| 服務容許嘅話用非預設端口 | 將遙距桌面或者管理端口轉去公開互聯網 |
| 俾服務加密碼或者金鑰 | 留低預設密碼 |
| 用完就刪規則 | 舊規則放幾年 |
| 自己遠端存取用 [VPN](../router/vpn.md) | 公開路由器自己嘅頁面 |

## 一定要公開嘅話

可以嘅話將裝置放喺獨立網絡，睇完風險之後，先考慮 [UPnP](../lan/upnp.md)、[觸發](../lan/port-triggering.md)同 [DMZ](../lan/dmz.md) 等替代方案。
