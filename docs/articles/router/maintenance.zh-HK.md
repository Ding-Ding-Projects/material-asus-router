---
title: 維護同重新啟動
summary: 重新啟動單一服務，或者喺兩個步驟確認之後重新啟動成部路由器。
---

維護係用嚟保養，唔係用嚟設定。你可以喺路由器某部分出問題時重新啟動嗰個服務，必要時先重新啟動成部路由器。因為重新啟動會令所有人斷線，所以有**兩個步驟確認**保護。

> [!NOTE]
> **開發中。** 服務重新啟動清單已經定義好，重新啟動連同兩步確認仲喺開發，真路由器測試未做。

## 重新啟動單一服務

重新啟動一個服務比重新啟動整部路由器溫和，建議先試呢個。

| 服務 | 幾時重新啟動 | 重新啟動期間會斷咩 |
| --- | --- | --- |
| Wi-Fi | 裝置加入唔到，或者訊號好似卡住 | 所有 Wi-Fi 裝置短暫斷線 |
| 派地址同 DNS | 裝置攞唔到位址，或者名稱解析唔到 | 新位址請求同查詢短暫暫停 |
| 防火牆 | 改咗規則但好似冇生效 | 現有連線可能重設 |
| 路由器網頁 | 路由器自己嘅頁面冇反應 | 只係路由器嘅頁面 |
| 時鐘 | 時間唔準 | 冇影響 |

### 步驟

1. 打開**維護**，揀服務。
2. 預覽會列出會斷咩，同大約幾耐。
3. 確認。如果服務可能影響你自己嘅連線，程式會啟動連線中斷保護。
4. 等狀態返嚟，然後測試。

## 重新啟動路由器

重新啟動會重啟所有嘢。遇到服務重啟都解決唔到嘅頑固故障、韌體改動之後，或者技術支援要求時先做。

> [!IMPORTANT]
> **兩個步驟。** 為咗避免誤按重新啟動，程式需要兩次獨立確認：先揀**重新啟動**，然後輸入螢幕顯示嘅字，或者確認第二個列明路由器同後果嘅提示。兩步規則係安全設計嘅一部分，任何角色都唔會跳過。

1. 打開**維護**，揀**重新啟動**。
2. 睇警告：成個網絡會斷幾分鐘，進行緊嘅下載同通話會停，Mesh 節點會重啟（[AiMesh](aimesh.md)）。
3. 完成第二個確認。
4. 程式發出重新啟動，並開始等路由器再次回應，有進度顯示。
5. 路由器返嚟之後，檢查**總覽**：運作時間應該好短。

如果路由器冇返嚟，等十分鐘再重新插電一次。復原步驟見[韌體](firmware.md)。

## 定期保養

| 工作 | 幾耐一次 |
| --- | --- |
| 做備份（[備份同還原](backup-restore.md)） | 每月，同每次大改動之前 |
| 檢查韌體更新 | 每幾個月 |
| 檢查[端口轉發](port-forwarding.md)同裝置 | 每幾個月 |
| 睇[記錄](logs.md)有冇重複失敗 | 覺得有問題嗰陣 |
| 排程重新啟動 | 通常唔需要；要定期重新啟動先正常嘅路由器，其實有故障值得查 |

## 原廠同 Merlin 嘅分別

| 項目 | 原廠 ASUS | Asuswrt-Merlin |
| --- | --- | --- |
| 服務重新啟動同重新啟動 | 有 | 有 |
| 排程重新啟動 | 可以用路由器自己嘅排程設定 | 可以用[排程工作](scheduled-jobs.md) |
