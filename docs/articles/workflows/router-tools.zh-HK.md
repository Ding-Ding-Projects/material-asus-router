程式可以喺**路由器上面**執行幾個診斷工具。呢點好重要：結果顯示路由器見到嘅，往往同你部電腦見到嘅唔同。呢啲工具已經做好，並喺模擬路由器核對過（見[網絡工具](../tools/network-tools.md)），但未喺真路由器試過。

## 四個工具

| 工具 | 回答嘅問題 | 輸入 |
| --- | --- | --- |
| Ping | 嗰個位址連唔連到、回覆要幾耐？ | 主機名稱或者 IPv4 位址，1 至 9 次 |
| Traceroute | 流量經過邊啲節點去到嗰度？ | 主機名稱或者 IPv4 位址，最多 15 跳 |
| 域名查詢 | 呢個名解析成邊個位址、邊個伺服器回應？ | 主機名稱 |
| 網絡喚醒 | 開啟屋企網絡入面休眠緊嘅裝置 | 裝置嘅硬件位址 |

## 睇 ping 結果（例子，唔係你路由器嘅）

```text
PING 203.0.113.9 (203.0.113.9): 56 data bytes
64 bytes from 203.0.113.9: seq=0 ttl=57 time=12.4 ms
64 bytes from 203.0.113.9: seq=1 ttl=57 time=12.1 ms
4 packets transmitted, 4 packets received, 0% packet loss
```

| 部分 | 意思 |
| --- | --- |
| `time` | 來回毫秒數，同一個國家內低過 30 算好 |
| `ttl` | 仲剩幾多跳，只係 traceroute 先重要 |
| `packet loss` | 冇返嚟嘅回覆。幾次之內超過 1% 就值得睇 |

## 診斷路徑

1. **Ping 路由器自己嘅位址。** 呢步失敗，問題喺你同路由器之間。
2. **用數字 ping 一個公開位址**，再**用名**。數字得、名唔得：係 DNS 問題，請睇 [DNS over TLS](../internet/dns-over-tls.md)。
3. **對慢嘅網站做 traceroute。** 時間突然跳高，或者某一跳開始全部星號，就知道延遲或者封鎖喺邊。單係星號未必係故障，有啲節點唔肯回答。
4. **域名查詢**顯示邊個伺服器回應同幾快。

## 程式點樣保障安全

- 主機名稱同位址送出之前會檢查。有空格、shell 字元或者格式錯誤嘅會被拒絕。
- 指令由程式用已驗證嘅部分組成，唔係你打嘅文字。請睇 [SSH 動作目錄](ssh-action-catalogue.md)。
- 輸出只作文字顯示同複製，永遠唔會被執行。
